# Native Metal FSR in the FH6 ARM64 container

This is an opt-in replacement for the upscaler provider used by OptiScaler in the FH6 Highball ARM64/FEX bottle. The existing OptiScaler frame-generation provider and game output settings are reused.

The Windows FidelityFX shim validates the descriptor and stages color, depth, motion and optional exposure textures in KosmicKrisp-backed D3D12 heaps. The vkd3d host-pass extension inserts a submission boundary in the original D3D12 list. It releases the Vulkan queue lock while waiting for the producer timeline, runs the native Metal encoder, then submits the rest of the list. The next D3D12 segment copies the result into the original game output so post-processing and frame generation see the new pixels. Unsupported dispatch layouts go through the original provider. A failure after the native pass has been scheduled reports device removal instead of submitting a consumer that would read stale pixels.

## Build and verify

1. Check out vkd3d-proton at `3b10bd7a7ec6a7347e616cf8bea59333afec2255` with its recursive submodules. Apply the `renderers-arm64` vkd3d-proton and dxil-spirv patches from Highball Engine at `8b315e7` as in its `build-renderers-arm64.yml`, then apply `vkd3d-host-pass.patch` at the vkd3d root.
2. Build the Windows x86-64 renderer with Highball's workflow. This build was also verified using LLVM MinGW 22.1.4. For that toolchain, the bundled dxbc-spirv `util/util_small_vector.h` needs an explicit `#include <new>`, and the dxil-spirv `scratch_pool.hpp` no-exceptions allocation failure path uses `#include <cstdlib>` and `std::abort()` in place of `std::terminate()`. Mark both renderer DLLs with the Wine builtin signature as in Highball's workflow and put them in the overlay's `aarch64-windows` directory.
3. Run `bash ../probes/verify.sh live` with the SDK and compiler environment used for the D3D12 probe, plus `VKD3D_HOST_OVERLAY` pointing at that overlay and `FFX_UPSCALE_DLL` pointing at the original AMD upscaler. This launches an isolated Windows process and calls the shim's public FidelityFX interface. Producer copies, the Metal dispatch, the output copy and AMD 3.1.6 frame generation are all recorded in one D3D12 command list. The probe requires a native dispatch and checks two generated intermediate frames at 3472 × 2266.

The verified artifacts for installation are `d3d12.dll`, `d3d12core.dll`, `amd_fidelityfx_upscaler_dx12.dll`, `fh6-fsr-bridge.so`, and `libfsr4-arm64.dylib`. Gather them in a directory and run `python3 install-live.py --artifacts DIRECTORY` with the game and Windows Steam closed. The existing AMD DLL is retained alongside the shim. The new renderer uses its own vkd3d disk cache because the renderer build identity differs. The previous cache stays on disk.

The live installation uses the existing precompiled Metal shader variants. The upstream compiler invokes `xcrun metal` even on a cache hit, so runtime compilation is disabled. Verify that the needed variants are present before deployment. The shim records the first native submission result and the first fallback per upscaler context in `OptiScaler-FH6-SDK/fh6-metal-fsr4.log`.

The live regression uses FH6's packed `R11G11B10_FLOAT` color and `R32G8X24_TYPELESS` depth. For the packed depth/stencil resource, the shim copies the float depth plane through a D3D12 buffer footprint into the shared `R32_FLOAT` texture. The original stencil plane stays in the game resource.

For a profile that prioritizes clean moving images, run `python3 visual-clean.py` against the installed OptiScaler configuration. The profile disables OptiScaler's frame generation and maps the Performance input to a 1.5× upscale ratio. It keeps the native output size and the Metal FSR provider. The script prints the location of the previous INI settings.

Use `--with-frame-generation` to keep 2× interpolation active while logging its dispatches and presents. For the KosmicKrisp GPU page-fault investigation, set `HB_KK_NO_UBO_ROBUST=0` in both the bottle and the FH6 game profile. Use separate vkd3d and Mesa shader cache directories for this setting so shaders compiled with unchecked uniform-buffer reads stay out of the test. Keep the original caches for the other configuration.

To restore the previous provider and DLL search path, close the game and Windows Steam and run `python3 install-live.py --rollback`. The original resolution, frame generation configuration and audio overlay remain in place. The GPU regression verifies the chain and texture contents. The game's launch, selected dispatch path, frame pacing and motion artifacts need an in-game run.
