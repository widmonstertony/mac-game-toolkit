## Evidence retention and next diagnostic

Original crash report, first-fault log, launch log, FG trace and batch log were
copied to a private local temporary evidence directory before further work.
Raw account/session data and licenses are not committed here.

`descriptor-observer.cpp` is a separate FH6-only, read-only ASI. It checks the
Store executable's timestamp and image size. Every ten seconds its low-priority
worker reads six pools' counters; it does not traverse free trees during normal
play. A filtered exception callback only copies the OS-provided context into
fixed storage and returns `EXCEPTION_CONTINUE_SEARCH`. The worker then records
the request-related registers and performs a bounded free-tree snapshot. It
never changes allocations or treats an exception as handled. Counter-stability
flags describe snapshot limits, not a claim of atomic consistency.

The Wine fixture verified no pool/batch mutation, wrong-exception rejection,
first-context retention, bounded free-tree output and unchanged exception
handling. The module was staged in the Store-only plugin directory and added to
the verified-files manifest, with a profile backup and successful launcher
check. It is diagnostic instrumentation, **not a crash repair**. It has not yet
been loaded in a new game process.

The existing fence observer reached its lifetime limit of 96 poll records
before the crash. Its absence of later records cannot be used to assert an
absence of later stalls. None of the retained data identifies which CPU thread
or complete GPU dependency chain caused the earlier ~1 second waits.
